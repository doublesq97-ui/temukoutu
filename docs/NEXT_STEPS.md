# 后续开发顺序

## P1：先提升可验证的质量与效率

1. 收集任务书的三张原始商品图，逐字检查文字、彩色装饰、细线和残留；把人工标注蒙版与许可信息纳入独立质量数据集。没有 GT 的照片只做人工检查。
2. 增加明确的前景/背景涂鸦种子层，避免现有完整蒙版引导把错误像素锁死；对低对比区域给出可解释的失败提示。
3. 接入可选交互式分割后端，要求模型下载前展示来源、许可证、大小并征得同意；模型按需加载，CPU 回退。对普通主体去背景结果保持印花核验，不直接认作正确。
4. 加入 OCR 原图/结果文字对照，提示漏字与断线；OCR 结果不能替代逐像素核验。
5. 改进边缘去杂色、相似色区域、阴影与半透明 Alpha 估计；单独测量黑描边和衣服同色场景，不用平均值掩盖失败。
6. 用分块/局部增量绘制提升 16MP 画笔效率；分割移到可强制终止的独立进程；加入磁盘配额、任务列表、到期清理与崩溃回收。
7. 基于内容哈希缓存参数与候选，之后增加批处理队列和批量下载。跨进程任务锁和版本冲突检测先于并发队列。
8. 可选重绘只作为独立的“生成/修复”输出，保留来源与标识，绝不能覆盖或冒充原图精准提取。

## P2：生产支持

先增加 DPI、物理尺寸、颜色数量分析和透明边缘质量检查，再评估 SVG 矢量化、非平面褶皱修复。修复无法恢复的信息必须明确标记，不承诺原始设计精度。

## P3：Codex Skill

封装现有 `python -m extractor_core.cli extract`，验证 JSON 状态及文件 Alpha，返回本地文件；遇到 needs_review 引导打开网页继续编辑。不得另建第二套算法。模型许可与下载授权保持在现有后端边界。
